## #2987 - The first traverse of a 3+2 plane is judged against the machine table

- **What was decided** (taken unattended; the maintainer can change it):
  1. **The table's top face, not its slab.** In a 3+2 frame, the law reads the machine table as its top face over the stated X/Y travel (the table box clipped to the Z travel, which starts at the table top). The slab under it (`MAX_FIXTURE_DIM` deep) is out of the tool's reach. Along an axis that tilts past 90 deg, the slab's underside read about 5e5 mm; the top face reads the real height. The table box already has the X/Y travel as its footprint (`fixture::table_of`), so "clip to the travel" needs only the Z clip.
  2. **Read the table only when the head tilts.** The machine file states which rotaries turn the work (`AxisLimits::turns_part`, #804). When each tilting rotary (axis not vertical) turns the work, the pose comes from turning the part. The tool stays upright in the machine frame, and the table stays under the work, so the stock top is the higher top. The index-swing clause (#1107) judges the work against the table in that case. The law then does not read the table. When a tilting rotary can be in the head (a head rotary, or an old file that does not state `turns_part`), or when the machine has no tilting rotary, the law reads the table top face along the tool axis. This is the conservative reading.
  3. **The table counts only where the move along the tool axis can carry the tool under its top** (found by the stack gate: a B 90 pocket on `tilthead.mch` at clearance Z95 was refused "under the fixture top Z625", and the `multiaxis-indexed` catalog case "under the fixture top at Z500"). Along a horizontal axis the table's far X edge reads as a high "top", but a move along that axis keeps the world Z. The rule: the worst start is on the table top face (the control does not know where the tool stands). The move along the axis from there to the plane changes the world Z by `(plane - h) * axis_z`. When the axis points up (`axis_z > 0`), the table counts if that move can drop the tool more than `Z_TOL` under the top, and the verdict names the top face's highest reading as the height to clear. The in-plane traverse then runs between two points over the table top, so it cannot go under it. A horizontal axis never counts the table. When the axis points down toward the table (past 90 deg, `axis_z < 0`), a higher plane stands lower in the world; the verdict can only say "raise", which is wrong there. So the path gets the note "...: the tool axis points down toward the table, so the move along it to the clearance plane can go under the table top" instead of a verdict. The earlier B 120 pin (pass at 100 mm, refuse at 90 mm) read the top face's highest corner, which is the wrong side for such an axis: the plane at 100 mm stands under the table top inside the travel.
     - Dropped: drop the table from every 3+2 reading (the #2985 law). A head tilt under 90 deg that dips under the table passes again (the B 30 and B 80 pins fail).
     - Dropped: a new `Warning` that says "lower the clearance plane" for an axis that points down. It changes the verdict type in `sim`, `app`, `ui` and the MCP surface. Recommended as a follow-up issue (P7).
     - Dropped: refuse each plane past 90 deg with the "raise" verdict. Its height to clear is wrong for such an axis, and a refusal with a wrong repair misleads.
  4. **No stated travel gives a note.** A mounted machine that does not state all of its X, Y and Z travel gives no table box (`fixture::table_of` needs the three). On a 3+2 plane that the table would judge, the path gets the note "First traverse: the machine table is not judged on this tilted plane: the machine does not state all of the X, Y and Z travel, so the first traverse is judged against the stock and the fixtures only". With no machine mounted there is no table, and no note (the unstated-limit law).
- **Why.** The #2985 law skipped the table in each 3+2 frame. A head-tilt plane drops toward the table on its low side, so a collision with the table passed. A plain read of the full table box refused each indexed operation on the microARC 4 (`first_4axis_part`, `fourth_axis_pose`, `index_swing`, `tilt_a180`, `tilt_a180_routes`). Even the top face alone refused them (Z 190.5 at A 90, Z 336.55 at A 180). Those refusals are false: that machine turns the work, and its table never stands over the plane.
- **Considered and dropped.**
  - Read the table in every frame, clipped: refuses each shipped 4th-axis example (false refusals, Done-when item 2 fails).
  - Read the table in the machine frame of a work-turning rotary: this needs the rotary axis line for an indexed operation. `fixture::rotary_axis_of` gives it only for the rotary kinds. No gain, because the table is under the work there.
  - Refuse when the machine states no travel: each 3+2 operation on a vendor file without travel would stop posting. A note is visible and does not stop a legal program.
  - A new `Warning` text for the table ("under the table top"): it changes the verdict type and the MCP surface. The existing "fixture top" text names the height to clear, which is the repair.
- **Not judged (known).** The law runs at generation only (as in #2985). Loading a different machine after a generate does not judge the first traverse again until the next generate. A machine with a head tilt and a vertical work C is read without the C turn of the footprint. A mixed machine, with a work-turning tilt (for example a table A) and a head tilt (for example a head B), reads the table top face in the setup frame: the part turn of the work-turning tilt is not in that reading.
- **Cost to change later**: low. One predicate (`work_tilts`), one clip (`table_top_face`) and one reading (`table_read`) in `operation/first_traverse.rs`.
